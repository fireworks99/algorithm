### 1.1.1 循环

循环，又叫迭代（iteration）。包含for循环与while循环，以及嵌套循环（循环里面再写循环）。



### 1.1.2 递归



#### 定义

递归是指**函数调用自身**。

包含两个阶段：“递”与“归”，向下递，向上归。

“递”的时候传递**更小或更简化**的参数，直到达到“**终止条件**”。

“归”的时候汇聚每一层的结果。



#### 比较

- 循环是“自下而上”解决问题，从起点出发走到终点
- 递归是“自上而下”解决问题，从终点出发走到起点



#### 缺点

每次递归，系统都会为新开启的函数分配内存，所以递归**耗费空间**。过深的递归会造成栈溢出。

递归比循环开销大，压栈（保存返回地址、参数、局部变量）、跳转、执行、弹栈、返回。这些操作在机器层面是实实在在的指令。而循环的每次迭代只是一次条件判断加跳转，开销小得多。所以递归**更耗时间**。



#### 优点

1. 很多问题本身就是递归定义的：树、图、分治、嵌套结构。**用递归写，代码几乎就是问题定义的直译**。例如：二叉树遍历、汉诺塔、全排列、组合生成。
2. 代码更短、更清晰、更易读
3. 天然支持分治与回溯



#### 尾递归

**如果函数在返回前的最后一步才进行递归调用**，则该函数可以被编译器或解释器优化，使其在空间效率上与迭代（循环）相当。这种情况被称为尾递归（tail recursion）。

~~~js
/* 尾递归 */
function tailRecur(n, res) {
    // 终止条件
    if (n === 0) return res;
    // 尾递归调用
    return tailRecur(n - 1, res + n);
}
~~~

但是斐波那契这种不是，这里函数返回前的最后一步是**求和**

~~~js
/* 斐波那契数列：递归 */
function fib(n) {
    // 终止条件 f(1) = 0, f(2) = 1
    if (n === 1 || n === 2) return n - 1;
    // 递归调用 f(n) = f(n-1) + f(n-2)
    return fib(n - 1) + fib(n - 2);
}
~~~
